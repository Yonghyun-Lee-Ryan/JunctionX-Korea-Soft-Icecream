# 역할 · 요구사항 추출

> [!important] 이 역할은 **해석하지 않는다.** 쪼개고 번호를 붙일 뿐이다
> [[06_트랙해부]]는 브리핑을 **읽고 판단한다**(파트너가 진짜 원하는 것, 사업적 동기). 이 역할은 그 앞 단계다 — **브리핑에 적힌 것을 적힌 그대로 항목으로 끊는다.**
> 판단이 섞이면 놓친다. 특히 **필수 조건**은 문단 끝에 한 줄로 붙어 있어서, 읽고 요약하는 순간 사라진다.

> [!success] 🟢 사람의 시간을 0분 쓴다 — 그게 이 역할의 설계다
> 8/21 **21:00~22:00은 파트너 워크숍**이라 4명 전부 자리에 없다. 그런데 브리핑 원문은 **20:00~21:00에 이미 손에 들어온다.**
> → **브리핑을 붙여넣는 즉시 던져두고 워크숍에 들어간다.** 22:00에 돌아오면 대장이 만들어져 있다.
> 2시간 창구(22:00~24:00)를 1분도 안 먹는 유일한 역할이다.

**언제**: 🔴 **8/21 20:00~21:00, 브리핑 원문 확보 즉시 던진다** · 미션 2·3 전 상태 갱신
**넣을 것**: **트랙 브리핑 원문 하나** + [[08_요구사항_대장]]의 빈 틀
**한 호출에 한 트랙.** 트랙이 여럿이면 트랙마다 하나씩 — 비교는 사람이 한다
**읽는 법**: **M(필수 조건)부터 본다.** 나머지는 22:00 이후에 읽어도 된다

> [!warning] 🔴 `00_고정`을 넣지 마라
> 이 역할은 **브리핑에 무엇이 적혀 있는지**만 뽑는다. 우리 제약·심사기준을 넣으면 모델이 *"우리가 할 수 있는 것"* 쪽으로 항목을 걸러내기 시작한다 — 그러면 **못 하는 요구가 대장에서 사라진다.** 못 하는 요구야말로 알아야 하는 것이다.
> 판정은 사람이 22:00에 [[06_트랙해부]] 카드와 나란히 놓고 한다.

## 붙여넣을 프롬프트

```
아래 트랙 브리핑에서 요구사항을 뽑아 항목으로 끊어라.
읽고 판단하는 게 아니라, 적힌 것을 적힌 그대로 쪼개는 일이다.

[트랙 브리핑 원문 전문]

## 시작 전 게이트
브리핑 본문이 비어 있거나 자리표시자만 있으면 만들지 마라.
"아직 브리핑이 없다"고 말하고 끝내라. 브리핑 없이 요구사항을 만들면
형식이 그럴듯해서 지어낸 티가 안 난다 — 이게 이 역할의 최악 실패다.

## 절대 규칙
1. 🔴 **인용은 원문 그대로.** 한 글자도 바꾸지 마라.
   - **번역하지 마라.** 영문이면 영문 그대로 둔다. 파트너가 쓴 단어가 곧 트랙 적합성이다
   - **요약하지 마라.** 문장이 길면 긴 대로 넣는다
   - 원문에 오타가 있으면 오타 그대로
2. 🔴 **브리핑에 없는 항목을 만들지 마라.** 일반적인 해커톤 요구사항을 채워 넣지 마라.
   갈래가 비면 "이 브리핑에는 없음"이라고 쓴다
3. **한 문장에 요구가 둘이면 둘로 쪼갠다.** 각각 번호를 준다
4. 어느 갈래인지 애매하면 **애매하다고 표시하고 둘 다에 넣는다.**
   놓치는 것보다 두 번 세는 게 낫다
5. 우리가 할 수 있는지 판단하지 마라. 아이디어를 내지 마라

## 갈래 다섯

### M — 필수 조건 (자격)
🔴 **이 갈래를 가장 먼저, 가장 꼼꼼히 훑어라.** 하나만 놓쳐도 나머지가 무의미해진다.

찾을 신호: must / required / at least one / have to / mandatory /
반드시 / 필수 / 제출물 형식 / 마감 시각 / 특정 API·플랫폼 사용 의무

🔴 **숨어 있는 자리를 반드시 훑어라** — 필수 조건은 제목 아래가 아니라
**문단 맨 끝 한 줄**, **Resources 절 끝**, **Evaluation 표 아래 각주**에 붙어 있는 일이 많다.
브리핑 전체를 **처음부터 끝까지** 훑고, 마지막 세 줄을 특히 다시 읽어라.

### W — 원하는 것
What we want to see / we would rather see / Directions we find interesting /
we are looking for. 각 불릿을 하나씩 끊는다.

### N — 원하지 않는 것
What we are not looking for / this already exists / we already have /
자사가 이미 한다고 말한 것. **이 갈래를 빠뜨리지 마라** — 여기 걸리면 즉사다.

### S — 배점
Evaluation / Judging criteria. 배점 숫자와 항목 문장을 원문 그대로.
배점이 없으면 "배점 미공개"라고 쓰라. **비율을 지어내지 마라.**

### R — 파트너가 주는 것
Resources / credits / dataset / API access. 한도·수량이 적혀 있으면 함께.

## 출력

각 갈래마다 표. 없는 갈래는 "이 브리핑에는 없음".

| ID | 원문 인용 (그대로) | 브리핑 어디에 (절 이름) | 애매함 |
| --- | --- | --- | --- |

ID는 M1, M2 / W1, W2 / N1 / S1 / R1 형식.

### 그리고 마지막에 셋

**① 개수** — 갈래별 항목 수. 총 몇 개인가.

**② 🔴 놓치면 실격인 것**
M 중에서 **지금 당장 확인·준비해야 하는 것**을 골라라.
계정 발급·플랫폼 등록·제출물 형식처럼 **시간이 걸리는 것**이 여기 온다.
각각에 "언제까지 해야 하는가"를 붙여라.

**③ 🔴 브리핑이 스스로 안 정한 것**
요구는 적혀 있는데 **판단 기준이 안 적힌 항목**을 골라라.
(예: "정직한 불확실성 처리"라고 적혀 있는데 무엇이 정직한지는 안 적혀 있다)
각각을 **파트너에게 물을 질문 문장**으로 바꿔라.
→ 이게 8/21 21:00 워크숍과 8/22 피드백 창구에서 쓸 질문이 된다.
```

## 읽는 법

**M과 ②만 22:00에 읽는다. 3분이면 된다.** 나머지는 23:00 이후 집필하면서 본다.

**③이 이 역할의 숨은 값어치다.** 브리핑이 요구는 적고 기준은 안 적은 자리 — 거기가 **다른 팀도 똑같이 모르는 곳**이고, 파트너에게 물어서 답을 받아 오면 그 답은 우리만 갖는다. [[10_발화채집]]이 만드는 차별화와 같은 종류인데, 이건 **무엇을 물을지 미리 알고 들어간다.**

**M이 0개로 나오면 의심하라.** 필수 조건이 하나도 없는 트랙 브리핑은 드물다. 프롬프트가 마지막 세 줄을 훑으라고 시키는 이유다.

## 쓰고 난 다음

1. 출력을 [[08_요구사항_대장]]에 **그대로** 옮긴다. 「우리 답」 칸은 비워둔 채로
2. **②를 즉시 처리한다** — 계정·등록·형식은 밤이 깊기 전에
3. **③을 [[04_현장메모]]의 워크숍 질문 목록에 붙인다**
4. 22:00 `/jx-harvest` 결과의 🔴 등급을 **F갈래**로 덧붙인다
5. 기능이 확정되면(23:00 이후) 「우리 답」·「상태」 칸을 채우고, 미션 2·3 전에 갱신한다

> [!tip] 미션 제출문의 목차가 이 대장이다
> 미션 1의 *"왜 그 트랙인가 / 무엇을 만드는가"*, 미션 3의 *"만든 것 / 안 만든 것과 이유"* 가 전부 이 표에서 나온다.
> 요구 ID를 그대로 인용하면 읽는 사람이 **세면서 읽을 수 있다** → [[09_미션제출]]
