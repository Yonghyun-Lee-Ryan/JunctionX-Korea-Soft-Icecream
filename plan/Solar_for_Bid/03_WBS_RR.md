```
1.1 응답 스키마 동결 (0.5h)
  └→ 1.4 Classify (1.5h) → 1.5 Extract 3 (2h) → 2.1 프리플라이트 (1h) → 2.2 되돌림 (0.5h)

       └→ 3.1 Agents API (3h) ──────┴→ 3.4 정규화 (2h) → 3.5 파일빌더 (3h) ─┐
```

**임계경로 합계 ≈ 23.5시간.** 🔴 벽시계는 32시간이 아니라 **28시간**이다(8/23 08:00 이후는 리허설·제출) → **여유 4.5시간**. 수면·식사·디버깅이 그 안에 들어가야 한다 — **여유가 없다.**

> [!error] 🔴 **2026-08-22 정정 — 아래 표의 원래 값 「Must 38ph(여유 25% 🟢) / 전체 46ph(여유 9%)」는 틀린 값이었다.**
> ① **38은 Must가 아니었다.** WBS 28행 단순합 46.5ph에서 **5.2~5.5(발표 덱·스크립트·리허설·제출) 8.5ph를 뺀 값**이 정확히 38.0이다. 즉 그 구분은 Must/Should가 아니라 **「발표 빼고 / 넣고」**였고, 발표는 뺄 수 있는 것이 아니다.
> ② **`전원` 행 둘을 1명분으로 셌다** — 4.1 E2E(2h)와 5.4 리허설(2h)은 4명이 붙으므로 각 8ph다(+12ph).
> ③ **지원(○)에 이름이 붙은 9개 행의 시수가 하나도 안 잡혀 있다.**
> → §0절의 그 함정과 같은 것이다. **집계 명령이 「무엇을 세는지」 눈으로 확인하지 않았다.**

| 범위 | 소요 | 가용 51ph 대비 |
|---|---:|---:|
| WBS 28행 단순합 | 46.5ph | 여유 9% |
| ＋ `전원` 행 보정(4.1·5.4 × 4명) | **58.5ph** | 🔴 **7.5ph 초과** |
| 🟢 **§6 단위 분해로 다시 짠 값** | **51.4ph** | 🟡 **여유 0** — §6-3의 절삭 사다리를 미리 정해 뒀다 |

→ 🔴 **Should 5는 「시간 남으면 하는 것」이 아니라 「지금 범위에서 빼는 것」이다.** 28시간 무박에서 여유 9%는 여유가 아니다 — Parse가 표를 못 살리거나(R2), 다중 입력이 안 되거나(R9), 배포가 한 번 막히면 그 자리에서 초과한다. **설계는 이미 Must/Should를 갈라 놨는데 일정이 안 잘랐다.**

> [!error] 🔴 정정 (04:30) — 여기 있던 「6~8ph 재작업」은 **틀린 수였다**

**그래서 응답의 바깥 구조만 얼린다** → `04_계약/factsheet.envelope.json`
(영어로는 response envelope. 🔴 **한국어로 「봉투」라 부르지 않는다** — 조달에서 봉투는 가격제안서를 밀봉하는 그 봉투다)

```
{ caseId, status, progress[],
  verdict:{ badge:"eligible", unverified:int, decision:"pending|go|skip",
            headline, reasons:[{text,page,docId,confidence}] },

```

🔴 **대신 치르는 값도 적어 둔다 — 공짜가 아니다.** 열 이름이 어긋나도 **빌드가 안 깨진다.** 전부 문자열이라 타입 검사가 못 잡고, **어긋남이 데모 시점(≈18:00)에야 드러난다** — 되돌림 시계 10:00보다 뒤다.

| **08:30** | 프리플라이트 | 총괄표 M(손으로 셈) · 추출 N | 🔴 **N/M ≥ 0.9이고 ※ 행이 1건 이상 → 조견표 유지. N/M < 0.9 → 그 자리에서 조견표를 빼고 WBS로 좁힌다.** 두 숫자와 판정 단어가 채팅에 한 줄 |
| **10:00** | 마지막 되돌림 | 🔴 **08:30 생존율과 06:00 R9 판정, 둘뿐이다** | 봉투 실물·「기간 명시 K건」은 이 시각에 **존재할 수 없다**(정규화 완료는 ≈17:00) — 그것들을 입력으로 삼던 결정(원가 탭)은 **지금 「뺀다」로 미리 닫았다** |
| **21:00** | Config 고정 | E2E 통과(19:30) | 🔴 **00:00에서 앞당겼다.** 순서: 21:00 Config 고정(정운) → 22:00 캐시 굽기(길정민) → 23:00 GIF·덱 채우기(주예진). 00:00에는 대조가 아니라 **미션2 문안만** 남는다 |

🔴 **정규화 완료 시각을 다시 계산했다 — 「≈13:30」은 근거 없는 값이었다.** 길정민 체인: 09:00 착수 → Agents API 4.3h → 12:30 → 정규화 4.5h(S3 1.5 + S4 1.5 + S5 1.3 + S6X 0.2) → **≈17:00.** 이전 문서의 다섯 개 인계가 전부 13:30을 기준으로 후속을 배치하고 있었다. 🟢 **이용현이 대기하지 않는 이유는 X2 게이트다** — 09:00에 화면③가 `demo.json`만으로 이미 완주해 있다.

### 6-5. 반영하지 않은 지적과 그 이유 — 한 줄씩

| 지적 | 왜 반영하지 않았나 |
|---|---|
| 봉투에 `attachments[].state` 옵셔널 필드를 추가해 부분 실패를 담자 | 🔴 **동결을 여는 값은 파일 수정이 아니라 「열 수 있다」는 선례다.** `progress[].detail` 문자열이 같은 것을 봉투 무변경·프론트 0줄로 보인다(S2 안 B) |
| X2를 3.0h 제작 단위로 남기고 S3·S4·S6X 프론트를 0으로 | S 레인은 단위별 dod로 검증되고 X2의 고유 가치는 09:00 한 시각뿐이다. 지우는 쪽을 X2로 잡았다 |
| E2E를 전원 2h(8ph)로 계상 | 두 사람 1.5h(3ph) + 정운 0.5h로 줄였다 — 정운·주예진이 같은 시간에 스크립트·덱을 진행하는 편이 산출물이 많다 |
| `calendar.js`를 이용현이 만들어 길정민에게 넘긴다 | 🔴 **파일 자체를 삭제했다.** 공휴일 출처가 문서에 없고, 출처 없는 배열 하드코딩은 §5-5 하드룰을 우리 코드가 먼저 어기는 것이다 |
| 이용현이 `downloads[]` 배열을 만든다 | `tabs[]`에서 결정적으로 파생되므로 **봉투 조립 함수 한 개(길정민)** 안에서 만든다. 이용현은 url 규칙 한 줄과 파일 라우트·빌더만 |
| 이용현이 xlsx 빌더와 화면③ 표를 둘 다 갖는 것이 중복 | 🟢 **중복이 아니다 — 같은 봉투를 읽는 두 출력 어댑터다.** 한 사람이 쥐면 두 번째가 싸다. 중복이 되는 유일한 경로(탭별로 나눠 쓰기)는 두 dod가 막는다 |
| `handoffs[]`에 hours 필드를 추가해 자동 합산 | 규칙 대신 **원칙 한 줄**로 대체했다 — 🔴 **인계물이 「만드는 일」이면 그 사람의 레인에 시수로 올린다.** 이번 분해에서 발견된 누락의 절반 이상이 「제안」과 인계물에 숨어 있었다 |
