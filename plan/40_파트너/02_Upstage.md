🔴 **이 한 줄이 기획을 직접 막는다.** *"확신도가 낮으면 사람에게 넘긴다"* 같은 **human-in-the-loop 라우팅을 Solar 모델로는 지금 못 만든다.** 모르고 설계하면 8/22 새벽에 막힌다.
⚠️ `Auto`가 무엇을 고르는지는 화면에 안 나온다 → E칸 질문

### A5. Classify의 Split · 스키마 · others (p.17·22·23)

| 무엇 | 화면 원문 |
| --- | --- |
| **Split** | *"하나의 파일에 여러 종류의 문서가 포함되어 있을 경우, 스키마 레이블을 기준으로 문서를 분리합니다."* (토글. **예제에서는 꺼져 있다**) |
| **스키마** | *"식별하고 싶은 레이블을 추가하고 편집하세요."* / 영문 `Add and edit the classes you want to identify.` |
| **필수 항목** | 🔴 **`레이블*`과 `설명*`이 둘 다 별표(필수)다** — **설명을 잘 쓰는 것이 분류 품질을 좌우한다**는 뜻 |
| **기본 클래스** | `others` — *"위 문서 클래스에 속하지 않는 문서"* |
| **자동 생성** | 스키마 자동 생성 버튼이 있다 |

### A6. Extract 출력 형태 (p.19)

`Preview` / `JSON` 두 탭. 출력은 **키-값 + 중첩 테이블** 둘 다다.
- 키-값: `applicant_name` `policy_number` `effective_date` `expiration_date` `premium_amount` `business_address`
- 중첩 테이블: `lines_of_business` (열: `premium` / `insurance_type`)
- 🔴 **일부 값 옆에 ⚠️ 경고 마커가 붙는다**(예제에서 `business_address`). **무엇을 뜻하는지 화면에 설명이 없다** → E칸 질문

### 🔴 A7. Instruct 출력 형태 (p.21) — **판정 + 근거 + 다음 행동을 한 번에 낸다**

인보이스 하나를 넣은 결과 화면:

| 자리 | 화면 원문 |
| --- | --- |
| 최상단 | `Decision: Unallowable Items` — **후속 라우팅에 쓰는 판정 키** |
| 본문 | `Status: Rejected — Unallowable Items` / `This invoice contains line items that violate AP policy and cannot be processed. Please return to vendor for a corrected invoice.` `[1]` |
| 근거 | `Flagged line items:` — Holiday party catering (deposit) — violates: Holiday party catering `[2]` / Bulk gift card purchase - vendor appreciation — violates: Gift cards `[3]` |
| 다음 행동 | `Next step:` `Return to vendor; do not extract or post to JDE.` `[4]` |

🔴 **`[1] [2] [3] [4]` 인용 번호가 원문으로 역추적된다.** 이게 p.21의 `Source-grounded insights`의 실물이다.
🔴 **그리고 이것이 `getting the work done`의 실행 지점이다** — Instruct가 **판단 + 근거 + 다음 행동**을 한 번에 낸다. p.21의 프롬프트 예시도 이 형태를 그대로 시킨다.
⚠️ **[[04_데모시나리오]]가 지목한 「관습적 화면」과 겹친다** — 원문 좌표 하이라이트 + 인용 번호는 **덱이 세 번 자랑한 그림**이다. 그대로 만들면 60팀과 같아진다.

## D. 건드리면 안 되는 것 — ✅ **트랙 확정(2026-08-21)으로 이 ①~⑦은 우리 제약이다**

**🔴 ① 페이지 수·토큰 수를 줄여주는 방향** — **페이지당 과금**이다. "덜 파싱해도 되게" 만드는 건 파트너 매출을 직접 깎는다. 게다가 비용 최적화 레버는 **이미 회사가 쥐고 있다**(가격표의 Auto mode).
✅ **덱이 이 판단을 강화한다** — p.9 `3M+ — pages automated daily`. 페이지가 곧 규모 지표다.

**🔴 ② Solar를 다른 LLM으로 갈아끼우기 쉽게 보여주는 것** — 이미 OpenRouter·OpenAI 호환 API로 나가 있다. 교체 용이성을 내세우면 **자기 락인을 스스로 깎아 보여주는 셈**이다.
⚠️ **단 이번 트랙의 락인 지점은 모델이 아니라 Studio(워크플로)다.** 필수 조건이 Solar가 아니라 **Studio**를 지목했다 — `*Upstage Studio must power the core document-processing stages.`

**③ 실제 금융·보험 고객 데이터 전제** — 반출이 안 된다. 금융 망분리(전자금융감독규정 제15조). 쓸 수 있는 건 **공개·합성 문서뿐**이다.
✅ **덱이 왜 데이터가 못 나오는지를 설명해준다** — p.9 `70% — insurance claims processed in Korea`. 🔴 **그리고 이것이 B-2 해석 ①과 맞물린다** — 엔터프라이즈 문서를 못 주니 **학생 손에 있는 messy 문서**로 Studio를 돌리게 하는 구조다.

**④ Solar License 표기 의무** — 파생 모델은 이름에 **"Solar" 접두사** + **"Built with Solar"** 표기.
⚠️ 이번 트랙 우선순위는 낮다 — **과제에 파생 모델 제작이 없다.**

**🔴 ⑤ 두 가지는 정치적으로 민감하다**
- **모델 출처 의혹** — 2026-01 Solar Open 100B의 중국 GLM 파생 의혹 제기 → 회사가 다음 날 **공개 검증회**를 열어 학습 로그 전면 공개 → 제기자 공개 사과. **"Solar가 정말 자체 모델인가"를 건드리지 마라**
- **공적자금 특혜 논란** — 국민성장펀드 5,600억을 두고 "만년 적자 특혜" 보도. **부스에서 재무를 들이대지 마라**

**⑥ 이미 한 것** — 노코드 문서 워크플로 빌더(Studio) · 문서 Q&A+인용(AI Space `[덱없음]`). *아숙업(AskUp)은 2023년 160만 이용자였으나 현재 제품 라인업에 없다 — **종료 발표는 못 찾았다. 단정 금지.***

**🔴 ⑦ 브리핑에 적힌 예시 4개를 그대로 고르는 것** (2026-08-21 신설) — 브리핑 Background의 `scholarship applications · housing lease contracts · part-time employment contracts · club expense receipts`는 **60팀이 같이 읽었다.** 그대로 가면 `Idea Creativity (25) — Is the problem discovery fresh?`가 직격이다.
