# 금지목록

> [!note] 왜 이 문서가 지시문보다 강한가
> **"이런 걸 해라"보다 "이런 건 안 된다"가 출력을 훨씬 잘 좁힌다.** 그리고 버린 아이디어를 기록하지 않으면 모델은 **같은 걸 또 제안한다** — 대화창을 새로 열 때마다 기억이 없으니 당연하다.
> 대회 중 **가장 자주 갱신되는 파일**이 이것이어야 한다. 뭔가를 버릴 때마다 30초만 써서 여기 적는다.

## 쓰는 법

아이디어를 버릴 때마다 한 줄. **버린 이유를 반드시 같이 적는다** — 이유가 없으면 나중에 "그거 왜 안 됐지?"로 되돌아온다.

```
| 버린 것 | 언제 | 왜 버렸나 |
```

## 처음부터 제외 — 해커톤 기획의 상시 금지

대회와 무관하게 항상 적용되는 것들. 모델이 자주 흘러가는 방향이라 미리 막는다.

| 금지 | 이유 |
| --- | --- |
| **"~를 위한 플랫폼"** | 플랫폼은 양면 시장이라 48시간에 한쪽도 못 채운다 |
| **사용자 수·시장 규모 추정치를 지어내기** | 심사 질의응답에서 가장 먼저 깨진다. 출처 없는 숫자는 아예 쓰지 않는다 |
| **"AI로 ~를 해결"만 있고 어떻게가 없는 기획** | 심사위원이 매년 수십 개를 본다. 차별점이 0 |
| **로그인·회원가입·관리자 페이지 만들기** | 데모에서 점수가 안 되는데 시간을 가장 많이 먹는다 |
| **완성도 낮은 기능 여러 개** | 하나가 확실히 도는 게 셋이 반쯤 도는 것보다 항상 낫다 |
| **트랙 과제를 비틀어 하고 싶은 걸 하기** | Challenge Partner는 **자기 과제의 답**을 보러 왔다 |

| **팀이 배우고 싶은 기술·주제를 트랙 선택 기준에 넣기** | 트랙은 파트너의 과제로 고른다. 학습 욕구는 스택 선택([[02_팀과_제약]] A)에서만 쓴다 |
| **발표 앞부분을 배경 설명으로 쓰기** | 3분 중 2분을 배경에 쓰면 정작 만든 걸 못 보여준다 |

### 🔴 AI 활용이 권장인 대회라서 생기는 것

이 대회는 AI 활용을 권장하고, **팀 4명 중 3명(기획·개발2)이 Claude Max를 쓴다.** 그런데 그건 다른 팀도 마찬가지다.

> 아래에서 **"3명"은 Claude Max 사용자 수**, **"4명·넷"은 팀 전체**다. 컨텍스트 공유 규약은 **디자이너 포함 4명 전원**에게 적용된다.

| 금지 | 이유 |
| --- | --- |
| 🔴 **"AI로 만들었다"를 차별점으로 내세우기** | **전원이 AI를 쓰는 대회다.** AI를 썼다는 건 기본값이지 자랑이 아니다. 차별점은 *무엇을 만들었나*에서 나온다 |
| 🔴 **팀원이 각자 다른 컨텍스트로 AI를 돌리기** | 넷이 따로 돌리면 산출물이 조용히 어긋난다. **`00_고정/` 4개를 네 사람이 같은 내용으로** 넣는다 → 아래 「팀 AI 규약」 |
| **AI가 뱉은 걸 검증 없이 산출물에 붙이기** | 특히 숫자·출처·기술 스펙. Expo 질의응답에서 그대로 깨진다 |
| **AI에게 "좋은 아이디어 10개" 시키고 고르기** | 확산만 하고 수렴이 없다. 방향은 [[03_회의론자]]로 **깎아서** 정한다 |

### 팀 AI 규약 — 세 사람이 같은 곳을 보게 하는 최소 규칙

1. **`00_고정/` 4개 파일은 매 호출마다 전원이 동일하게 넣는다.** 이게 팀의 공유 기억이다 → [[04_사전결정]] 포함
   ✅ **공유 수단은 GitHub 확정**(2026-08-18). 볼트 레포를 클론하면 **대회 중 갱신이 자동 반영된다** — 노션이었다면 수동 복사라 갱신이 안 갔다
2. **버린 아이디어는 즉시 이 파일에 적는다.** 안 적으면 다른 팀원의 AI가 그걸 또 제안한다
3. **한 사람이 한 역할.** 같은 산출물을 둘이 동시에 AI로 고치지 않는다 — 머지 충돌이 문서에서도 일어난다
4. 기획(나)이 `20_산출물/`의 **단일 소유자**다. 개발·디자인의 입력은 받아 적되 파일은 한 사람이 쓴다

## 표현 금지

산출물에 쓰면 안 되는 어법. 발표 스크립트에서 특히.

- "혁신적인", "획기적인" — 형용사는 근거를 대신하지 못한다
- "~할 수 있습니다" (미래형 가능성) → **"~합니다"** (지금 되는 것만)
- "향후 확장 가능" — 안 만든 걸 만든 것처럼 들리게 하는 어법. 질문 받으면 무너진다
- 데모에 없는 기능을 있는 것처럼 말하기 → **Expo 3시간 동안 반드시 들킨다.** 부스에 오는 사람 중엔 48시간 직접 만든 개발자가 섞여 있다

- **"사용자가 불편해합니다"로 문제를 세우기** → **"이 회사는 지금 이걸 이렇게 처리하고 있습니다."** 파트너가 말한 현재 처리 방식을 그대로 인용한다. 비용·시간 숫자는 **파트너가 말한 것만**
- **"저희 팀이 관심 있는 주제라서"** — 질의응답에서 이 말이 나오면 트랙 적합성이 그 자리에서 깎인다. 이유는 항상 파트너 쪽에서 댄다
