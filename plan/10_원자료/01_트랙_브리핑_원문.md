- Chat 화면(p.12) 하단 모델 선택기에는 **`Solar Open 2`**가 붙어 있다 — 🔴 p.5 제품 타임라인에 없는 이름이다(아래 「덱의 제품 타임라인」 콜아웃)

**Split · 스키마 · others**

- **Split** — *"하나의 파일에 여러 종류의 문서가 포함되어 있을 경우, 스키마 레이블을 기준으로 문서를 분리합니다."* 토글이고 **예제에서는 꺼져 있다**
- **스키마** — 한글 *"식별하고 싶은 레이블을 추가하고 편집하세요."* / 영문 `Add and edit the classes you want to identify.` 🔴 **`레이블*`과 `설명*`이 둘 다 필수 항목(별표)이다**
- **`others`** 클래스가 기본 제공된다 — *"위 문서 클래스에 속하지 않는 문서"*
- 스키마 **자동 생성** 버튼이 있다

#### Extract 출력 화면 (p.19)

`Preview` / `JSON` 두 탭. 출력은 **키-값과 중첩 테이블 둘 다**다.

- 키-값: `applicant_name` · `policy_number` · `effective_date` · `expiration_date` · `premium_amount` · `business_address`
- 중첩 테이블: `lines_of_business` (열 `premium` / `insurance_type`)
- 🔴 일부 값 옆에 **⚠️ 경고 마커**가 붙는다(예제에서는 `business_address`). **무엇을 뜻하는지 화면에 설명이 없다** → [[05_워크숍_질문지]]

#### Instruct 출력 화면 (p.21) — **결정 + 인용 번호**

인보이스 1건을 넣은 결과 화면. 보이는 대로:

```
Decision: Unallowable Items

Status: Rejected — Unallowable Items
This invoice contains line items that violate AP policy and cannot be processed.
Please return to vendor for a corrected invoice. [1]

Flagged line items:
Holiday party catering (deposit) — violates: Holiday party catering [2]
Bulk gift card purchase - vendor appreciation — violates: Gift cards [3]

Next step: Return to vendor; do not extract or post to JDE. [4]
```

- `[1] [2] [3] [4]`는 **원문으로 역추적되는 인용 번호**다 — 위 p.21 원문 `Source-grounded insights — Trace every result directly back to the original document`의 실물
- 같은 슬라이드의 프롬프트 예시(위 「노드별 특징」 끝)가 **이 출력 형태를 그대로 시킨다** — `return this output verbatim with the bracketed sections filled in` / `## Status: Rejected — Unallowable Items`
