# 요구사항 대장

> [!error] 🔴 트랙 적합성은 인상이 아니라 **커버리지**다
> 심사에서 가장 자주 깨지는 항목이 트랙 적합성인데, 대부분의 팀은 브리핑을 **읽고 느낌으로** 답한다. 파트너는 자기가 쓴 요구를 하나씩 세면서 본다.
> 이 대장은 브리핑을 **항목으로 쪼개 번호를 붙이고, 각 항목에 우리가 답했는지 추적**한다. 그러면 미션 3과 Final Pitch에서 이 문장을 쓸 수 있다 — *"파트너가 적은 요구 N개 중 M개에 답했고, 나머지는 이런 이유로 안 했습니다."*
> **60팀 중 이 문장을 말하는 팀은 거의 없다.**

> [!error] 🔴 이 대장의 진짜 값어치는 M(필수 조건)이다 — 실격 방지
> 브리핑에는 **필수 조건이 산문 속에 숨어 있다.** 리허설 브리핑에도 실제로 있었다 — *"Teams must use at least one Upstage API"* · *"Teams must deploy at least one component on Azure"*.
> 이건 요구가 아니라 **자격**이다. 하나만 놓쳐도 나머지를 아무리 잘해도 소용없다. 그런데 **요약하는 순간 가장 먼저 사라지는 문장**이기도 하다 — 문단 맨 끝에 한 줄로 붙어 있기 때문이다.
> → 그래서 이 대장은 **원문 인용 그대로** 옮긴다. 번역도 요약도 하지 않는다.

**언제 채우나**: 🔴 **8/21 21:00~22:00 워크숍이 도는 동안 에이전트가 만든다** — 사람 시간을 안 먹는다
**갱신**: 22:00 발화 반영(F갈래) · 8/22 미션2 전 · 8/23 미션3 전
**만드는 법**: `/jx-req` → [[15_요구사항추출]]

| --- | :---: | :---: | :---: | :---: | :---: |
| **M 필수 조건** | | | | | — |
| W 원하는 것 | | | | | |
| N 원하지 않는 것 (안 했나) | | | | | — |

🔴 **M에 「안 함」이 하나라도 있으면 제출 불가로 판정한다.** 기능을 더 만들기 전에 이것부터 채운다.
🔴 **N은 「안 했나」를 센다.** 파트너가 원하지 않는다고 적은 것을 우리가 하고 있으면 그건 감점이 아니라 즉사다 → [[03_회의론자]] 즉사 ①

| ID | 원문 인용 (그대로) | 우리가 이걸 하고 있나 | 근거 |

🔴 **하나라도 「예」면 그 기능을 즉시 잘라낸다.** 이건 논의 대상이 아니다.
**이 표는 [[13_기업해부]] C(이미 있는 것)와 짝이다** — 브리핑에 안 적혔지만 파트너가 이미 파는 것도 여기 붙인다.

| --- | :---: | --- | --- | :---: |
| S1 | % | | | |
| S2 | % | | | |

🔴 **배점이 가장 큰 칸이 화면으로 안 보이면 그건 트랙 선택 신호다** → [[04_사전결정]] D-2 순위 규칙 1 · [[06_트랙해부]] 6-b
🔴 **배점 순으로 데모 시간을 배분한다.** 40%짜리 항목을 90초 중 10초로 보여주고 있으면 [[04_데모시나리오]]를 다시 짠다.

## 🔴 브리핑과 고정 문서가 부딪칠 때

**트랙 브리핑 원문이 `00_고정`을 이긴다.** 어긋난 항목은 즉시 [[04_현장메모]]의 워크숍 질문 목록 맨 위로 올린다.

> 2026-08-19 리허설에서 이게 없어 에이전트가 판단을 **20회 보류**했다. 가짜 브리핑의 상금이 [[01_심사기준]] 상금표와 어긋났는데 우선순위 규칙이 하네스 어디에도 없었다.
> 가짜 자료라서 난 충돌이지만 **8/21에 진짜로 난다** — 브리핑은 그날 처음 보는 문서고 고정 문서는 일주일 전에 쓴 것이다.

## 안 채우면 무슨 일이 일어나나

**요구를 세지 않으면 「많이 답한 것 같은 느낌」으로 제출하게 된다.** 그러면 두 가지가 일어난다 — M을 하나 놓쳐서 자격에서 떨어지거나, 배점 40%짜리 칸을 90초 데모에서 10초만 보여준다. 둘 다 실력이 아니라 **세지 않아서** 지는 것이다.
